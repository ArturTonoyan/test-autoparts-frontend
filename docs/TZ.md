# Техническое задание

Клиентское приложение на React для поиска автозапчастей и аналогов через API Favorit Parts.

## Цель

Двухэтапный подбор номенклатуры: сначала производители по артикулу, затем аналоги и предложения по выбранному бренду.

## API

Источник: [wsprice.pdf](https://lk.favorit-parts.ru/static/wsprice.pdf)

| Параметр   | Описание                                      |
| ---------- | --------------------------------------------- |
| `key`      | Ключ покупателя                               |
| `number`   | Артикул детали                                |
| `brand`    | Производитель (опционально)                   |
| `analogues`| `on` — вернуть аналоги (нужен `brand`)        |

Базовый URL: `http://api.favorit-parts.ru/hs/hsprice/`

Этап 1: `?key=…&number={артикул}` → список брендов  
Этап 2: `?key=…&number={артикул}&brand={бренд}&analogues=on` → аналоги и предложения

Цена берётся из `warehouses[].price`, остаток — из `warehouses[].stock` / `count`.

## Функциональность

### Этап 1 — производители

1. Поле ввода артикула.
2. По отправке формы — запрос списка производителей.
3. Список брендов для выбора.

### Этап 2 — аналоги

1. Выбор бренда → запрос с `number` + `brand` + `analogues=on`.
2. Таблица/список позиций с полями:
   - название / производитель;
   - стоимость;
   - остаток на складе.

## Стек

- React (hooks), JavaScript ES6+ без TypeScript
- Redux Toolkit — состояние UI (этап, выбранный бренд, артикул)
- TanStack Query — запросы к API, кеш, повтор
- React Hook Form + Zod — валидация формы поиска
- Mantine 8 + Tabler Icons — UI-компоненты и тема
- Vite — сборка

## Нефункциональные требования

- Лоадеры на время запросов
- Обработка ошибок API, сети, пустых ответов
- Адаптив (мобильный / десктоп)
- Простая и читаемая архитектура
- Юнит-тесты на ключевую логику (маппинг ответа, валидация)

## Структура приложения

```
src/
  api/          — клиент Favorit Parts
  store/        — Redux slice
  features/     — поиск, бренды, результаты
  components/   — UI-примитивы (Loader, ErrorAlert)
  utils/        — нормализация данных
```

## Этапы реализации

1. Инициализация проекта, конфиг, клиент API
2. API-слой и утилиты нормализации ответа
3. Redux + React Query, форма поиска
4. UI этапов 1–2, состояния загрузки/ошибок
5. Тесты, README, финальная полировка

## Критерий готовности

Пользователь вводит артикул → выбирает бренд → видит аналоги с ценой и остатком. Ошибки и пустые ответы обрабатываются без падений UI.
